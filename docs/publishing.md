# 提交、审核与发布

开发中心：https://relinkus.cn/plugins/

## 提交前

1. 使用自己的插件 ID；不要保留示例 ID。准备公开 GitHub、GitLab 或 Gitee 源码仓库。
2. 将源码、素材及许可证提交到仓库，记录完整 commit SHA。上传包必须与该提交对应。
3. 使用 `node tools/pack.cjs <源码目录> <名称>.unsigned.rlplugin` 打包。不要自行签署。
   最终签名安装包上限为 100 MiB（界面显示 100 MB）；Base64 编码也计入包大小。打包器会为授权信息预留 1 KiB，超过上限须缩小资源后重新打包。
4. 在独立预览环境测试键盘操作、状态变化、断线、退出登录及资源开销。

## 官网提交

在提交表单选择开发包，提供源码仓库、完整 SHA、许可证、联系邮箱和审核说明，确认代码与素材的发布权。初版提交服务无需注册额外管理账号，作者身份和插件 ID 归属由控制台人工核实；填写邮箱本身不代表身份已认证。

提交成功后保存 JSON 查询凭证。凭证含 submissionId、receipt 与 contentHash，用于在官网查询本次审核状态；它不能授权、更新或删除插件。不要公开查询凭证。服务不自动发送邮件。

状态：待审核 → 已授权 / 已退回；已授权 → 已撤销。退回后修订源码并重新提交。每个已授权或已撤销版本不得复用，新更新使用新的版本号。

## 控制台核验

审核人员检查每个上传资源、源码提交一致性、ID 归属、第三方依赖、申请能力、代码与素材许可及真实宿主行为。代码详情只显示文本，不在控制台执行。

拥有版本发布权限的管理人员可以查看队列；授权、退回和撤销要求最高管理员权限。授权必须填写原因并完成三项核验确认。服务端再次核对内容指纹，使用独立保管的 Ed25519 私钥签名，操作记录保留审核人、原因及时间。

## 下载与撤销

官网只提供已授权签名包。不要改变签名包中的任何字节对应的内容。更新代码、素材、权限或版本都必须重新审核。

撤销立即关闭官网下载，签名撤销清单位于 `/plugins-api/revocations`。已安装插件的撤销检查由客户端宿主执行，在线清单支持情况取决于宿主版本；离线客户端使用随客户端发布的撤销名单。


## 提交新版本

保留插件 ID 和已审核的源码仓库，提高三段式版本号，再提交源码 SHA 与开发包。每个版本单独审核、签名；审核前不会进入更新目录。客户端提示新版本后由用户点击安装，不自动下载或替换。权限增加时额外确认，只重启该插件，保留用户设置。完整三态浮窗要求 apiVersion: 2 与 Relink 1.0.6 补丁 1；一般插件可继续使用 API v1。
